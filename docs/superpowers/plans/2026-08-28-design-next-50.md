# Merzavtsy Design Next 50 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close fifty actionable open requirements from the approved `merzavtsy-design.md` while preserving soulbound identity, bounded state, deterministic behavior, replay safety, and no-custody economics.

**Architecture:** Extend canonical World state only where the approved design explicitly requires canonical gameplay facts (needs, XP sources, biography transitions, mutation eligibility). Keep presentation, specialization projection, metadata/SVG, history search, analytics, and explanations off-chain as deterministic read models over canonical state/events. Extend daemon activity history with durable metrics instead of making raw transaction cadence an on-chain concern.

**Tech Stack:** Solidity 0.8.34, OpenZeppelin 5.6.1, Hardhat 3.14, TypeScript 5.9, viem 2.56, Node 22 SQLite, node:test.

**Spec:** `docs/superpowers/specs/2026-08-28-merzavtsy-design.md`

## Global Constraints

- One non-transferable creature per account.
- Every bounded numeric state remains within 0..10000 unless its type has a narrower documented range.
- XP is monotonic and never creates financial rewards.
- Activity ingestion remains EIP-712 signed, replay-protected, and hard-capped.
- No proxy upgrades, project token, custody, yield, gambling, paid stat boosts, or caller rewards.
- Deterministic gameplay randomness is used only for non-financial branching.
- Existing Activity category indexes 0..9 remain stable.
